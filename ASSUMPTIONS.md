# Assumptions — Transaction Ledger API

## 1. Account Management
- Each account is assigned a unique ID generated by the server.
- Account names are required and must not be blank.
- Every new account starts with a balance of zero.
- The initial balance and account creation timestamp are controlled by the server.

## 2. Transactions
- Only `credit` and `debit` transaction types are supported.
- Transaction amounts must be greater than zero and have no more than two decimal places.
- Transaction descriptions and reference IDs are required and must not be blank.
- Transaction timestamps are generated by the server.
- A reference ID must be unique within an account but may be reused by another account.
- A credit increases the account balance by the transaction amount.
- A debit decreases the balance only if sufficient funds are available.
- A rejected transaction must not change the account balance or create a successful transaction record.

## 3. Data Integrity
- Successful transaction records are intended to be immutable through the API.
- Account balance updates and transaction creation must succeed or fail together.
- Duplicate transaction requests for the same account and reference ID are rejected.
- Database constraints provide an additional safeguard against duplicate references.

## 4. Transaction History
- Transactions are returned newest first.
- The optional `type` parameter filters transactions by `credit` or `debit`.
- Pagination starts at page 1.
- The default page size is 10, and the maximum page size is 100.
- An empty result set returns zero total records and zero total pages.

## 5. Error Handling
- A nonexistent account returns HTTP `404 Not Found`.
- An insufficient-funds debit returns HTTP `400 Bad Request`.
- A duplicate reference ID returns HTTP `409 Conflict`.
- Invalid request data returns HTTP `422 Unprocessable Content`.

## 6. Technology and Scope
- The application uses Python, FastAPI, SQLAlchemy, SQLite, and Pydantic.
- Automated API tests use pytest and FastAPI's test client.
- Authentication, authorization, multi-currency support, and external payment processing are outside the current assignment scope.
